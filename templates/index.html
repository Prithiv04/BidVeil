Verification availability

BIDVEIL performs cryptographic verification through the official NEAR AI Inference SDK. A gateway signature proves the response passed through the verified NEAR AI gateway. A provider_tee signature additionally proves the model executed inside a Trusted Execution Environment. BIDVEIL never displays MODEL_TEE_VERIFIED unless the backend returns that state.

    Verification lifecycle

    Official SDK order
    1. Fresh nonce generated

      32-byte per-request nonce prevents replay of stale attestation evidence.

    2. Attestation report fetched

      Live report retrieved from NEAR AI Cloud for the resolved TEE model.

    3. Nonce binding verified

      Gateway, model and NVIDIA payload attestations must echo the session nonce.

    4. SDK attestation verified

      Official InferenceClient.verify() validates the attestation chain.

    5. Inference executed

      Chat completion runs on the verified model; request/response retained.

    6. Response signature verified

      verify_response() checks signature kind and signed payload hashes.

    7. Result delivered

      Verification object attached to the evaluation response.

    What BIDVEIL does

    • Validates file type, size and structure before processing.
    • Extracts text ephemerally — originals are never stored.
    • Sends bid text to NEAR AI Cloud only for the active evaluation.
    • Generates a fresh 32-byte nonce per evaluation (replay protection).
    • Deletes temporary files after the request, including failures.
    • Does not intentionally persist uploads, prompts, or responses; does not log tender content.

    Limitations — read before use

    • BIDVEIL cannot guarantee physical memory erasure.
    • NEAR AI Cloud's retention and logging policies are outside BIDVEIL's control.
    • Verification proves inference integrity, not data privacy at the provider.
    • Do not submit information unless the provider's terms are acceptable to your organisation.
    • Cleanup is confirmed per-request in the processing log; check it after each run.
