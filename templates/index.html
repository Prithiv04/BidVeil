What is cryptographically verified

  • Attestation report — fetched live from NEAR AI Cloud and bound to a fresh per-request nonce.
  • SDK attestation — verified by the official NEAR AI Inference SDK (client.verify).
  • Response signature — verified by the SDK (client.verify_response) against the retained request and response bytes.
  • Signed payload — parsed and model-id bound by BIDVEIL as a secondary check.

If the provider returns a gateway signature, BIDVEIL reports GATEWAY_ONLY. Model-level TEE execution is claimed only for provider_tee signatures.

Privacy & data handling

  1. Documents are uploaded to BIDVEIL for this evaluation only.
  2. Readable text is extracted in request-scoped processing; originals are never stored.
  3. Bid text is sent to NEAR AI Cloud for analysis — BIDVEIL cannot control the provider's retention or logging practices.
  4. Each evaluation uses a fresh cryptographic nonce; attestation reports must echo it, preventing replay of stale evidence.
  5. Model TEE verification is shown only after the official SDK validates a provider_tee signature. A gateway signature is never treated as model TEE proof.
  6. Temporary server-side files are removed after the request, including failures.
  7. BIDVEIL does not intentionally persist uploaded files, extracted bid text, prompts, or model responses, and does not log tender content.

BIDVEIL cannot guarantee physical memory erasure or control NEAR AI Cloud's retention policies. Do not send information unless the service's terms are acceptable to your organization.

Verification states

  • WAITING — no verification performed yet.
  • ATTESTATION_PENDING — attestation report requested.
  • ATTESTATION_VERIFIED — report fetched and nonce-bound.
  • SIGNATURE_VERIFIED — response signature verified by the SDK.
  • MODEL_TEE_VERIFIED — provider_tee signature verified; model executed in a TEE.
  • GATEWAY_ONLY — gateway signature verified; model TEE execution not proven.
  • VERIFICATION_FAILED — a cryptographic check failed.
  • VERIFICATION_UNAVAILABLE — verification could not be performed (e.g. provider billing/connectivity).
